# Vendor workspace

The approved-vendor application starts at `/vendor/dashboard`. It uses React, Tailwind utilities, scoped workspace CSS, Lucide icons, Express REST APIs and the existing MSSQL database. All menu entries lead to working pages with live records, loading, error and empty states. No demonstration business records are seeded into the application.

## Setup

1. Preserve the existing MSSQL, JWT and SMTP environment settings.
2. Run `npm run db:migrate` in `backend`. Migration `008-vendor-workspace` adds `Services.AttributesJson`, a nullable vendor scope on `Coupons`, and attachment name/MIME metadata on `Messages`. Existing global coupons remain global and are not editable through vendor APIs.
3. Configure the existing server-only Cloudinary credentials for service/logo/cover images, verification documents and chat attachments. Images accept PNG/JPEG; documents and attachments accept PDF/PNG/JPEG, up to 5 MB. Private documents/attachments are uploaded as authenticated raw assets. Browser requests receive upload tokens or protected downloads rather than private storage URLs.
4. Start the backend and frontend using their existing `npm run dev` commands. Sign in as an approved, active vendor. The server requires migration 008 before startup.

The frontend derives `/api/vendor` from `VITE_GRAPHQL_URL`. Optionally override it with `VITE_VENDOR_API_URL`. Keep credentials out of frontend environment variables.

| Area                  | Routes and behavior                                                                                                                                                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dashboard / Analytics | `/vendor/dashboard`, `/vendor/analytics`: nine lifetime KPIs; daily, weekly and monthly revenue; booking count; revenue by service/category; recent requests and upcoming celebrations                                                    |
| Business              | `/vendor/business/profile`, `/vendor/business/details`: contact, business identity, GST/PAN, public logo/cover, categories and locations; changes are audited                                                                             |
| Verification          | `/vendor/verification`, `/vendor/documents`: current application/cycle, document status, private downloads and additional document submission; previous documents remain intact                                                           |
| Services              | `/vendor/services`, `/vendor/services/new`, `/vendor/services/:id`, `/vendor/services/:id/edit`: view, create, edit, duplicate, activate/deactivate; category-aware fields for all 17 categories                                          |
| Packages / Items      | `/vendor/packages`, `/vendor/packages/new`, `/vendor/packages/:id/edit`, `/vendor/items`: service-owned packages, included items, prices, discounts, guest limits, durations, featured and active status; service-item management         |
| Availability          | `/vendor/calendar`, `/vendor/availability/blocked`, `/vendor/availability/available`: month calendar, booking/request overlays, available/blocked ranges up to 91 days, all-day or timed entries, service-specific or business-wide scope |
| Bookings              | `/vendor/bookings/requests`, `/upcoming`, `/active`, `/completed`, `/cancelled`: server-filtered lists; view, accept/reject pending requests, create quotations and start customer conversations                                          |
| Quotations            | `/vendor/quotations/new`, `/drafts`, `/sent`, `/accepted`, `/rejected`, `/vendor/quotations/:id/edit`: draft/send proposals with line items, package selection, discounts, tax and expiry; edit drafts, send, cancel and inspect outcomes |
| Customers             | `/vendor/customers`: customers related through this vendor's bookings, quotations or conversations                                                                                                                                        |
| Payments              | `/vendor/earnings`, `/vendor/payouts`, `/vendor/transactions`: recorded gross/commission/tax/net earnings, payout status, and customer payment transactions; read-only financial records                                                  |
| Reviews / Promotions  | `/vendor/reviews`, `/vendor/offers`, `/vendor/coupons`: own reviews and publication status; create/edit/activate/deactivate vendor-owned offers and coupons                                                                               |
| Communication         | `/vendor/messages`, `/vendor/notifications`: customer conversations, associated booking/event, unread counts, chat history, private files and notifications with mark-read actions                                                        |

`service-templates.js` is the single source of truth for dynamic forms and attribute validation. The catalog API sends the same schema used by the backend. Attributes are validated against the selected active category; unknown fields and invalid types are rejected. New/edited services become Pending and require admin approval. A duplicate is initially inactive and Pending. Selected service categories are added to the vendor's business categories. Package prices are computed by MSSQL from original price and discount.

## REST API

All endpoints are under `/api/vendor`. Read endpoints return `{ success: true, data: ... }`; mutations return `{ success: true, message, id? }`. Errors return `{ success: false, message, data: null }` with appropriate HTTP codes. Collections support `page`, `pageSize` (maximum 100), search on relevant fields, and allowlisted status filters.

| Method     | Path                                                                                                         | Purpose                                                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET        | `/workspace`, `/dashboard`, `/catalog`, `/business`                                                          | Authenticated business identity, analytics, category schemas and own catalog, business details                                                                                |
| PUT        | `/business`                                                                                                  | Update business details with `expectedUpdatedAt` protection                                                                                                                   |
| GET        | `/records/:section`                                                                                          | Own services, packages, items, locations, documents, availability, bookings, quotations, customers, revenue, payouts, transactions, reviews, offers, coupons or notifications |
| POST       | `/images`, `/documents`                                                                                      | Signed image uploads and private verification documents                                                                                                                       |
| GET        | `/documents/:id/file`                                                                                        | Vendor-scoped private document download                                                                                                                                       |
| POST / PUT | `/services`, `/services/:id`                                                                                 | Create/edit service with validated category attributes; approval reset to Pending                                                                                             |
| POST       | `/services/:id/duplicate`                                                                                    | Clone own service, items and image as inactive Pending copy                                                                                                                   |
| GET        | `/services/:id`, `/packages/:id`, `/locations/:id`, `/items/:id`, `/offers/:id`, `/coupons/:id`              | Scoped edit/detail data                                                                                                                                                       |
| POST / PUT | `/packages`, `/packages/:id`                                                                                 | Save package and included items atomically                                                                                                                                    |
| POST / PUT | `/locations`, `/locations/:id`, `/items`, `/items/:id`, `/offers`, `/offers/:id`, `/coupons`, `/coupons/:id` | Manage owned business records                                                                                                                                                 |
| PATCH      | `/:kind/:id/active`                                                                                          | Activate/deactivate own services, packages, locations, offers or coupons                                                                                                      |
| POST       | `/bookings/:id/decision`                                                                                     | Accept/reject Pending booking; rejection needs a reason; write booking history and notify customer                                                                            |
| GET        | `/quotation-options`, `/quotations/:id`                                                                      | Events linked through own bookings/quotations and owned package options; quotation details                                                                                    |
| POST / PUT | `/quotations`, `/quotations/:id`                                                                             | Create or edit a Draft proposal, compute totals and save line items atomically                                                                                                |
| POST       | `/quotations/:id/action`                                                                                     | Send draft or cancel an eligible quotation; only active, approved services and active packages can be sent                                                                    |
| GET / PUT  | `/calendar?month=YYYY-MM`, `/availability`                                                                   | Month availability/bookings; update available/blocked date ranges                                                                                                             |
| GET / POST | `/conversations`                                                                                             | Own customer conversations; start a conversation from an owned booking                                                                                                        |
| GET / POST | `/conversations/:id/messages`                                                                                | Cursor-paginated history and sending text/private attachments                                                                                                                 |
| POST       | `/conversations/:id/attachments`                                                                             | Private upload token bound to vendor, user and conversation                                                                                                                   |
| GET        | `/conversations/:id/messages/:messageId/attachment`                                                          | Scoped private download without exposing stored URLs                                                                                                                          |
| PATCH      | `/conversations/:id/read`, `/notifications/:id/read`                                                         | Read receipts and owner-scoped notification updates                                                                                                                           |

Chat polls for updates every 10 seconds while the page is visible. History loads in 50-message pages using a timestamp + message-ID cursor. Attachments are optional; text-only messages are fully functional. Customer messages are read from the shared Conversations/Messages tables, and outgoing vendor messages generate customer notifications. This workspace does not replace the separate customer application.

## Ownership and business rules

Every route and service operation requires an authenticated, verified, active user with an active Vendor role, an existing Approved vendor and an active business. State is loaded from the database by the existing cookie authentication. Mutations require the exact frontend Origin and `X-Vendor-Request: 1`. Payloads cannot assign VendorId, approval decisions, computed totals, payment settlement or customer identity. Parent ownership is verified for package/item/service relationships. GUID validation accepts SQL Server sequential GUIDs as well as RFC UUIDs.

The collections allowlist excludes internal audit logs, verification notes and authentication data. Record identifiers are checked against the current vendor before reads or writes. Coupons with null VendorId remain outside vendor scope. Customer event options are restricted to events already linked through the vendor's bookings or quotations; another event belonging to the same customer is not automatically disclosed. Accepted/rejected quotation status remains customer-controlled. Existing bookings and financial records are preserved when catalog records are deactivated.

Booking acceptance honors blocked availability. Blocking a range with an accepted/confirmed/in-progress booking is rejected, and recorded Booked availability cannot be overwritten through this interface. Booking decisions, quote writes and messages produce audit/history/notification records in the same transaction. Service/package/location edits use update timestamps where supported by the schema. Financial views do not initiate transfers, refunds or settlement updates.

Revenue KPIs/charts use successful INR payment collections; failed and foreign-currency payments do not enter those totals. Payment rows retain their own currency. Service/category charts allocate collections proportionately by booking item value; missing item allocations are not fabricated. Earnings and pending payouts use the separate payout ledger. Ratings use published reviews. Time series are filled with real zero buckets where there was no activity. Reporting dates and month calendars use Asia/Kolkata.

## Verification

Run `npm test` and `npm run build` in backend/frontend respectively. `node scripts/verify-vendor-workspace.js` exercises the real REST API and MSSQL database with temporary fixtures: all 17 category attribute forms, service edits/duplication, items/packages, calculated discounts, locations, vendor/global coupon separation, booking decisions, quotations/totals and event isolation, availability conflicts, messaging and private downloads, notifications, every collection, daily/weekly/monthly analytics, cross-vendor denial and a live rejection access check. It rolls back all fixture rows, audit entries and notifications, then removes its temporary PDF. Cloudinary network upload behavior is covered separately by the existing upload tests and requires configured credentials for live upload checks.
